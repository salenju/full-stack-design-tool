| 项 | 内容 |

## 1. 背景与问题定义

### 1.1 现状

从「一张 UI 设计图」到「一个能跑的前后端应用」，目前需要人工完成五次手工翻译：

1. 读设计图 → 在文档里写接口清单和字段（人脑翻译，易漏、易漂移）
2. 写接口文档 → 前后端各自实现（文档与实现双份维护）
3. 写页面 → 前端照着设计图重画，字段名与接口对不上时靠口头确认
4. 写假数据 → 手搓 mock，字段类型和关联关系经常不自洽
5. 写业务逻辑 → 从零开始，AI 也因为没有结构化上下文而只能猜

每一次翻译都会有信息损耗，而损耗在校验环节才暴露，返工成本最高。

### 1.2 问题本质

不是「缺一个画图工具」，也不是「缺一个 AI 写代码的工具」，而是**缺一个把「界面意图」固化为「机器可读契约」的中间层**。只要这个中间层存在且可校验，代码生成和 AI 生成才是有根之木。

### 1.3 产品定位（一句话）

> 一个可视化工作台：在画布上把「页面 / 接口 / 数据表 / 字段」以及它们之间的调用与映射关系连成一张图，工具把这张图编译成可校验的契约（OpenAPI + UI Schema + 示例数据），再据此生成 Vue 3 前端与 NestJS 后端代码，并让 AI 在确定性的骨架上只填业务逻辑。

### 1.4 与 BRD 的差异（修订说明）

| BRD 原方案 | 本 PRD 修订 | 修订理由 |
|---|---|---|
| OpenAPI 是「唯一真相源」 | 画布 IR 是唯一真相源，OpenAPI 是派生产物之一 | OpenAPI 无法表达页面结构、调用链路、页面跳转，作为唯一源会丢信息 |
| IR 只有 `api / model / table` 三类节点 | 增加 `page` 页面节点与 UI 组件描述 | 否则只能生成类型化 HTTP 客户端，生成不出页面 |
| 设计图导入降级为「背景图 + 手动画框」 | 双通道导入：Figma 结构化导入 + 图片视觉识别，均产出「待确认字段候选」 | 直接回应核心诉求，同时用「人工确认」控制准确率风险 |
| 后端固定 Spring Boot | 生成目标为 NestJS + Prisma；生成器做适配器抽象，Spring 作为 P2 扩展 | 与本项目 Vue 3 技术栈一致，降低维护两套语言的成本 |
| 画布选型待定（tldraw / React Flow / Plait） | 定为 Vue 3 + Vue Flow | 用户已确认 Vue 3；Vue Flow 原生支持句柄级连线，适合字段级映射 |
| 未涉及往返与漂移 | 列为 P1 一级功能（生成区标记 + 三方合并） | 否则工具只能跑一次，二次生成即失控 |
| 无校验环节 | 增加契约校验（Lint）与生成前门禁 | 让产物可信，是工具被长期使用的必要条件 |

## 2. 目标与非目标

### 2.1 目标

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 设计图 → 字段候选 → 契约，全流程在同一工作台闭环 | 从导入设计图到导出可运行代码，全程不离开工具、不手写接口文档 |
| G2 | 契约可校验、可版本化、可评审 | 存在 Lint 规则集，且生成前必须通过（可配置为告警） |
| G3 | 生成的代码是「能编译、能启动、类型对齐」的骨架 | 生成物通过 `vue-tsc` / `tsc --noEmit`，后端可 `nest build` 启动 |
| G4 | AI 只在骨架上填业务逻辑，不发明接口 | AI 输出的路由/字段集合必须与契约一致，否则拒收 |
| G5 | 一次建模，多端产出 | 由同一 IR 产出 OpenAPI、UI Schema、示例数据、前端页面、后端模块、AI 上下文包 |
| G6 | 二次生成安全 | 手工改动不被静默覆盖，冲突可审阅 |

### 2.2 非目标（本期不做）

- ❌ 不做像素级还原的「设计稿转静态页面」（不做 visual-to-HTML 保真度竞赛）
- ❌ 不做运行时低代码平台（不提供在线运行的应用容器、不做表单引擎）
- ❌ 不替代 Figma / 飞书画板（不追求自由绘图、图片编辑、矢量能力）
- ❌ 不做多人实时协作（P2 才考虑，P0 只保证单人 + 文件可交换）
- ❌ 不做生产级权限/审批/多租户
- ❌ 不生成数据库迁移的线上执行（只生成 SQL/Schema 文件，执行由人决定）
- ❌ 不做 AI 自动「理解整个需求文档并一键出全站」

## 3. 用户与角色

| 角色 | 描述 | 主要诉求 | 关键操作 |
|---|---|---|---|
| **全栈工程师（主用户）** | 独立开发者或小团队成员，Vue + Node 背景 | 少写重复代码，接口与页面一次对齐 | 导入设计图、建节点、连线、导出代码 |
| **前端工程师** | 拿到契约写页面 | 字段名/类型/枚举不用猜，示例数据可直接跑通 | 消费 UI Schema 与类型定义、审查生成页面 |
| **后端工程师** | 拿到契约写接口 | DTO 与校验规则自动生成，减少对齐成本 | 消费 OpenAPI 与 NestJS 骨架 |
| **设计/产品** | 提供设计稿、确认字段语义 | 确认工具识别出的字段是否准确 | 在候选确认面板逐条确认/驳回 |
| **AI 编码助手** | 非人类参与者 | 需要结构化、可裁剪、无歧义的上下文 | 消费 AI 上下文包，输出业务逻辑实现 |

## 4. 核心概念与术语

| 术语 | 定义 |
|---|---|
| **项目（Project）** | 一个工作区，包含一张或多张画布，产出一套契约与代码 |
| **画布（Canvas）** | 画布视图，按「领域/模块」可拆分多张 |
| **节点（Node）** | 画布上的实体，含 4 类：数据表、接口、页面、备注/分组 |
| **字段（Field）** | 数据表/接口/页面组件的属性，是**有稳定 ID 的一等实体**，在节点上渲染为「端口」 |
| **端口（Port/Handle）** | 字段在画布上的可连线锚点（左侧入、右侧出） |
| **连线（Edge）** | 表达语义关系，分 5 类：调用、读取、写入、映射、跳转 |
| **IR** | 画布的结构化表示，是唯一真相源，可导出为 JSON 并版本化 |
| **契约（Contract）** | 由 IR 编译出的产物集合：OpenAPI 3.1、UI Schema、示例数据 |
| **UI Schema** | 描述页面结构的中间表示：布局类型 + 区块（筛选表单/表格/表单/动作）及其字段绑定 |
| **字段候选（Field Candidate）** | 从设计图识别出、尚未确认的字段建议，带置信度与来源定位 |
| **上下文包（Context Pack）** | 为 AI 生成准备的裁剪后 JSON，按流程/页面分片，带 token 预算 |
| **生成区（Generated Region）** | 生成文件中被标记的区块，重新生成时可被安全替换 |
| **Lint** | 契约一致性校验规则集 |

## 5. 端到端用户场景

### 场景 A：从 Figma 设计稿到可运行骨架（主路径）

1. 用户新建项目「设备管理」，粘贴 Figma 文件链接 + 节点 ID，配置 Personal Access Token。
2. 工具拉取节点树，识别出 2 个页面框架、1 个表格、1 个搜索表单、1 个新增弹窗，产出 **14 条字段候选**，每条带置信度、来源图层名、在画布上的高亮框。
3. 用户在「候选确认」面板逐条确认：8 条采纳、2 条改名、2 条改类型、2 条驳回。驳回项可选「记入忽略规则」。
4. 用户把确认后的字段落到「设备」数据表节点与两个页面节点（「设备列表页」「新增设备页」），并新建 `GET /devices`、`POST /devices` 两个接口节点。
5. 用户连线（四类边各出现一次）：
   - **调用**：`设备列表页.查询按钮 → GET /devices`
   - **读取**：`GET /devices 响应.deviceName → 设备表.device_name`
   - **写入**：`POST /devices 请求.sn → 设备表.sn`
   - **映射**：`GET /devices 响应.deviceName → 设备列表页.表格.deviceName 列`（同名字段展示映射）
6. 工具实时 Lint：提示「`GET /devices` 缺少分页参数」「`设备表.sn` 必填但新增表单未绑定控件」「`设备列表页` 路由与已有页面冲突」。
7. 用户修复后点击「生成」。
8. 产出：OpenAPI 3.1（`openapi.yaml`）、UI Schema、示例数据（`seed.json`，含 50 条设备且外键自洽）、Vue 3 前端（类型 + 请求客户端 + 两个页面）、NestJS 后端（module/controller/dto/service 骨架 + Prisma schema）。
9. 用户点击「AI 填充业务逻辑」，选择「设备列表分页查询」流程，AI 只填 `device.service.ts` 的三处 `// @dsg:todo`，输出通过类型检查后落盘。
10. 用户导出 zip，本地 `pnpm i && pnpm dev` 即可启动，页面能查到示例数据。

### 场景 B：只有截图，没有 Figma 源文件

同场景 A，第 2 步改为上传 PNG/JPG 截图。工具调用视觉模型，输出字段名称、控件类型、位置框、置信度；**低置信度项默认不采纳**，用户必须逐条确认。其余流程一致。

### 场景 C：已有后端，只想补前端

用户跳过「接口节点」的自动生成，改为导入已有 OpenAPI 文件，工具反向生成画布节点（逆编译），再补充页面节点与组件绑定，只导出前端代码。

### 场景 D：AI 写入后人工改动，再次生成

用户手工修改了 `device.controller.ts`（在生成区外新增一个自定义接口）。再次生成时，工具检测到生成区哈希不一致，弹出三方对比（上次生成 / 当前文件 / 本次生成），用户可以「保留我的改动」或「接受新生成」，冲突逐块处理。

## 6. 功能需求

优先级定义：**P0** = MVP 必须；**P1** = 第一版完整交付；**P2** = 后续增强。

### 6.1 项目与工作区

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-101 | 创建/重命名/删除项目，项目列表带缩略图与最近打开时间 | P0 | 项目落盘为独立目录，重建索引后可恢复 |
| FR-102 | 一个项目支持多张画布（按模块拆分），画布间可引用同一数据表 | P0 | 跨画布引用节点时，字段改动双向同步 |
| FR-103 | 自动保存（防抖 800ms）+ 手动快照（带备注） | P0 | 崩溃后重开不丢最近 1 次操作；快照可回滚 |
| FR-104 | 导入/导出项目包（`.fsdt.zip`：IR + 素材 + 配置） | P1 | 在另一台机器导入后可完整继续编辑 |
| FR-105 | 项目设置：目标框架、包管理器、输出目录、命名规范、语言（TS/中文注释开关） | P0 | 设置影响所有生成产物 |

### 6.2 画布与节点编辑

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-201 | 无限画布：平移、缩放、框选、多选、对齐辅助线、网格吸附 | P0 | 缩放范围 10%–400%，60fps 下 200 节点拖动不掉帧 |
| FR-202 | 四类节点：数据表、接口、页面、备注/分组；每类有独立外观与图标 | P0 | 节点类型可转换（如接口→备注），转换时保留字段 |
| FR-203 | 节点内联编辑字段：增删改排序、类型选择、约束（必填/长度/枚举/默认值/正则） | P0 | 全部操作可撤销/重做（≥50 步） |
| FR-204 | 页面节点可挂组件：筛选表单、表格、表单、详情、按钮/动作 | P0 | 组件可绑定接口与字段，未绑定时 Lint 报错 |
| FR-205 | 节点折叠/展开、按类型过滤、搜索定位（名称/路径/字段名） | P1 | 搜索命中后画布自动聚焦并高亮 |
| FR-206 | 复制粘贴、跨画布粘贴、批量改类型 | P1 | 粘贴时自动重算 ID 并修复内部引用 |
| FR-207 | 小地图、缩放控件、快捷键面板 | P1 | 快捷键可自定义 |

### 6.3 设计图导入（双通道）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-301 | **Figma 通道**：按文件 key + 节点 ID 拉取节点树，提取文本层、图层名、自动布局、组件实例名、输入框线索 | P0 | 拉取失败有明确错误分类（401/403/404/限流），可重试 |
| FR-302 | **图片通道**：上传 PNG/JPG（≤10MB），调用视觉模型识别字段、控件类型、位置框 | P1 | 返回结构化 JSON，含 bbox 与置信度；单张图 ≤60s |
| FR-303 | 两个通道统一产出 `FieldCandidate[]`，进入「候选确认」面板 | P0 | 候选面板支持：采纳 / 改名 / 改类型 / 驳回 / 记入忽略规则 |
| FR-304 | 候选去重与合并：同一字段多处出现时合并，保留来源列表 | P0 | 合并后不产生重复字段；来源可追溯 |
| FR-305 | 置信度分级：≥0.85 自动勾选，0.5–0.85 需人工确认，<0.5 默认不勾选 | P0 | 阈值可在项目设置调整 |
| FR-306 | 画布背景叠加：设计稿作为**画布背景层**铺底（非图片节点），支持透明度、缩放、偏移与锁定 | P0 | 半透明铺底不影响节点交互；背景不参与连线与校验 |
| FR-307 | 采纳候选时自动创建/合并到目标节点，并生成字段 ID | P0 | 采纳 14 条候选后，画布上无孤儿字段 |
| FR-308 | 导入结果可导出为 CSV，供非工具用户评审 | P2 | CSV 含名称/类型/置信度/来源/结论 |

### 6.4 字段级端口与连线

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-401 | 每个字段在节点两侧渲染为可连线端口（入=写入目标，出=读取来源） | P0 | 字段增减时端口自动重排，已连线不丢失 |
| FR-402 | 五类连线语义：调用（页面动作→接口）、读取（接口响应字段→表字段/页面组件字段）、写入（接口请求字段→表字段）、映射（字段→字段，可带转换表达式）、跳转（页面→页面） | P0 | 连线类型决定颜色/线型/箭头，图例可查 |
| FR-403 | 连线合法性校验：类型不兼容、自环、重复连线时给出即时提示 | P0 | 拖拽松开即提示，不阻塞但记录为 Lint 问题 |
| FR-404 | 映射转换表达式：支持 `trim` / `toNumber` / `dateFormat('YYYY-MM-DD')` / `lookup(表.字段)` 等内置函数 | P1 | 表达式可预览样例输入→输出 |
| FR-405 | 连线可加备注与分组（按流程高亮：选中某条流程时高亮相关链路） | P1 | 一条链路跨 3 个画布时仍能高亮 |
| FR-406 | 自动布局：按「页面→接口→表」分层排列 | P2 | 一键布局后无节点重叠 |

### 6.5 契约校验（Lint）

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-501 | 内置规则集（见 6.5.1），可分等级（error/warn/info） | P0 | 规则可单独开关；结果可点击跳转到对应节点/字段 |
| FR-502 | Lint 结果面板：按节点聚合、按严重度排序、支持「忽略此项」（记录原因） | P0 | 忽略项在 IR 中持久化，重新生成不丢 |
| FR-503 | 生成前门禁：存在 error 时禁止导出代码（可在设置中降级为警告） | P0 | 门禁可被显式跳过，但跳过记录进生成日志 |
| FR-504 | 自定义规则：以 JSON 声明式规则（必填字段集合、命名正则、路径前缀） | P2 | 自定义规则与内置规则同权 |

#### 6.5.1 内置 Lint 规则（P0 集合）

| 规则号 | 说明 |
|---|---|
| L001 | 页面动作（按钮/提交）未绑定任何接口 |
| L002 | 接口引用了不存在的表或字段 |
| L003 | 映射两端类型不兼容（如 string → number 且无转换函数） |
| L004 | 响应字段缺少示例值（影响示例数据与文档质量） |
| L005 | 必填字段在页面表单中无对应控件 |
| L006 | `method + path` 重复定义 |
| L007 | 列表类接口缺少分页参数（page/pageSize） |
| L008 | 枚举字段未声明取值范围 |
| L009 | 引用成环且无深度上限（示例数据无法生成） |
| L010 | 命名不符合规范（表 snake_case、字段 camelCase、路径 kebab-case） |
| L011 | 路径参数未在接口中声明对应字段 |
| L012 | 页面路由重复或与已有路由冲突 |
| L013 | 接口声明了 `auth: 'bearer'` 但项目 `settings.backend.auth = 'none'`（契约与实现不一致，由「不做 JWT 骨架」的决策引入） |
| L014 | 页面组件绑定的字段不在其接口响应/请求 DTO 中（字段改名后常见残留） |

### 6.6 示例数据生成

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-601 | 按数据表生成示例数据，默认每表 20 条（可配置 1–1000） | P0 | 字段类型、长度、枚举、正则、默认值全部满足约束 |
| FR-602 | 引用完整性：外键值必须存在于被引用表的示例集中（拓扑排序 + 环检测） | P0 | 生成后运行引用校验，0 处悬空引用 |
| FR-603 | 确定性：同一 IR + 同一 seed 生成完全相同的数据 | P0 | 两次生成文件字节级一致 |

## 7. 数据模型（PRD 视角）

### 7.1 实体关系

```
Project 1 ── n Canvas 1 ── n Node
Node(数据表) 1 ── n Field
Node(接口)   1 ── n Field（请求/响应分区）
Node(页面)   1 ── n PageComponent 1 ── n FieldBinding
Node 1 ── n Edge（source/target 指向 node + 可选 field 端口）
Project 1 ── n Snapshot（IR 全量快照 + 备注）
Project 1 ── n ImportJob（来源、候选、结论）
Project 1 ── n GenerationRecord（manifest、schemaHash、时间、AI 用量）
```

### 7.2 关键约束

- 字段 ID 全局唯一且**永不复用**（删除后也不回收），保证连线引用稳定。
- 接口的请求/响应字段分组独立（`request` / `response` / `pathParams` / `query`），同名不代表同字段。
- 页面组件的字段绑定通过「字段引用」而非「字段名复制」，重命名字段时自动跟随。
- 所有删除为软删除（保留 ID 与墓碑标记），以便快照回滚与引用修复。

### 7.3 字段类型系统（面向用户）

`string` / `number` / `integer` / `boolean` / `datetime` / `date` / `enum` / `object` / `array<T>` / `ref(表)` / `file` / `json`。

每个类型可附加约束：必填、可空、长度、范围、正则、枚举值、默认值、示例、单位、敏感标记。

## 11. 风险与对策

| 风险 | 影响 | 概率 | 对策 |
|---|---|---|---|
| 视觉模型识别字段准确率不稳定 | 核心卖点受损 | 高 | 双通道（Figma 结构化优先）；置信度分级 + 强制人工确认；把「确认」做成快速批量操作而非逐条点击 |
| 字段级端口让画布过于拥挤 | 可用性崩塌 | 中 | 节点默认折叠字段（显示前 5 条 + 计数）；「端口模式」独立开关；映射可在右侧属性面板用下拉选择，连线只是可视化 |
| 生成代码「能跑但没用」 | 用户流失 | 中 | 明确「骨架 + 待填」定位；把 AI 填充与 TODO 清单做成可追踪进度 |

| AI 幻觉出契约外字段 | 代码不一致 | 中 | 结构化输出 + 白名单校验 + 类型检查门禁 |
| 用户已有代码无法纳入 | 工具只能用在新项目 | 中 | P1 提供逆编译（OpenAPI → 画布）与「仅生成新文件」模式 |
| Figma API 限流/变更 | 导入中断 | 低 | 本地缓存节点树；导出 Figma 插件离线快照作为兜底 |

## 12. 已确认决策（2026-10-19 用户拍板）

以下 7 条原为开放问题，现已全部确认，不再作为待定项：

| # | 问题 | **决策** | 对需求的影响 |
|---|---|---|---|
| 1 | 生成前端 UI 库 | **只做 Element Plus** | 前端生成器只维护一套组件映射表；`settings.frontend.uiLib` 保留字段但不实现其它适配器 |
| 2 | 代码语言风格 | **不做 Options API 兼容** | 一律生成 `<script setup lang="ts">` + Composition API；模板数量减半 |
| 3 | NestJS 数据层 | **Prisma 7.x 为默认且显式锁定**；同时**保留 TypeORM 适配位** | `settings.backend.orm = 'prisma' \| 'typeorm'`，P1 只要 Prisma 实现；TypeORM 通过 `CodeGenerator` 适配器后置扩展 |
| 4 | JWT 认证骨架 | **不做** | P0 只生成 OpenAPI 的 `securitySchemes` 与 `security` 描述 + 在 `main.ts` / `client.ts` 留鉴权挂载点；不生成 auth module、登录页、refresh 逻辑 |
| 5 | 画布反向导出为图片/SVG/飞书 | **需要** | 新增 FR-709：P0 出 PNG/SVG，P1 出 Figma/飞书可消费的结构化导出 |
| 6 | 交付形态 | **本地服务 + 浏览器** | 无 Electron/Tauri 打包；服务仅监听 `127.0.0.1` |
| 7 | CLI | **需要** | 新增 6.11 节；IR 必须支持「文件模式」以便进仓库、进 CI |

> **由第 7 条引出的必要修正**：原设计把 IR 只存在 `~/.fsdt/`，CI 环境无法访问。现明确 IR 支持两种权威存储——**文件模式**（仓库内 `design/ir.json`，git 管理）与**服务模式**（`~/.fsdt/`，带 SQLite 索引），见技术设计 5.2。
